# VNext 阶段 0–1：基线与紧凑索引结论

记录日期：2026-08-08

## 隔离边界

- 真实 `%APPDATA%/Rime` 仅作为历史来源说明，本轮没有写入、部署或修改。
- 全量构建使用只读备份 `backups/rime-test-dictionaries-20260807/Rime`。
- 原型数据库只生成在项目 `Temp` 下，未接入当前 GUI 和正式配置目录。
- 未执行 PyInstaller、发布或 Git 操作。

## 旧索引基线

- 文件：`%LOCALAPPDATA%/RimeConfig/system_dictionary_index.sqlite`
- 大小：415,490,048 字节（约 396.2 MiB）。
- 总记录：3,554,253。
- 来源：万象 2,195,218；雾凇 1,263,546；万象英文 71,686；melt_eng 21,854；万象混合码 1,949。
- 结构主要空间来自重复文本/编码和两棵字符串索引。

## VNext 原型范围

- 当前方案：万象。
- 根词典：`wanxiang`、`wanxiang_english`、`wanxiang_mixedcode`。
- 解析源文件：21 个，共 79,976,554 字节。
- 词条：2,268,853。
- 每个方案使用独立 SQLite 文件；不把雾凇数据混入万象索引。

## 最终原型结构

- 一棵普通 SQLite B-Tree，键为“源文件 ID + 带用途域的 64 位指纹 + 块内记录号”。
- 原始字词、完整编码、权重和音节边界按 256 条组成 zlib 压缩块。
- 字词、全拼和严格简码分别使用不同指纹域；命中后必须解压原始值再次精确校验，因此指纹碰撞不会产生错误结果。
- `wut`、`wti` 不保存两份额外字符串索引，而是通过严格简码桶取得候选，再依据保存的音节边界精确验证。
- 单字简码、完整编码、字词反查均为精确匹配，不使用 `LIKE`、包含查询或 FTS5。
- 文件签名未变化时不复制索引；单文件变化时在副本内更新对应文件的压缩块和查找记录，再原子替换。

## 实测结果

- 最终大小：183,201,792 字节（约 174.7 MiB），较旧索引减少约 55.9%。
- 首次全量构建：约 211 秒；必须在未来的数据引擎进程后台执行，并提供进度、取消和原子切换，严禁阻塞 GUI 启动。
- 21 次热查询中位数：
  - `h`：约 13 ms，能命中“还”；
  - `wut`：约 19 ms，能命中“物体”；
  - `wti`：约 16 ms，能命中“物体”；
  - `wuti`：约 5 ms；
  - 按“物体”反查：约 5 ms；
  - 未命中查询：约 13 ms。
- 未变化刷新检查：约 35 ms，不生成索引副本。
- SQLite 查询计划：`SEARCH lookups USING PRIMARY KEY (file_id=? AND lookup_key=?)`。

## 已知边界

- 静态索引负责检索和词典浏览，不承诺复现 Rime 学习后的最终候选顺序；实际候选预览仍由按需 librime 进程提供。
- 简码候选采用有界分页读取；后续数据引擎协议必须携带游标或页信息，不能一次解压全部单字候选。
- 首次构建仍为分钟级，是后台任务而不是启动依赖。
- 动态 Lua 词典和实际前端方案识别仍属于后续阶段风险。
